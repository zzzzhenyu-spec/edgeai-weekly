# 端侧大模型知识分享 · 思维导图

以**思维导图**形式展示端侧大模型（On-Device LLM）基础知识：主干「端侧大模型」→ 领域分支（基础概念 / 压缩量化 / 推理与硬件）→ 概念卡。每张卡带一句话白话解释与带圈数字「建议阅读顺序」，点开看详解、关键数字与延伸阅读；地图下方是「公共知识区」——网络上值得一读的分享。

**全部内容数据驱动：加一个知识点 = 在数据文件里加一个对象，不碰任何代码。**

- 纯静态、零依赖、无网络请求：双击 `index.html` 即可离线打开
- 暗色主题，青 / 紫 / 橙三色分支，连线端点几何级精确贴边
- 支持搜索、入门/进阶筛选、分支收起、建议阅读顺序、`#node/<id>` 深链分享

## 快速开始

```bash
git clone https://github.com/zzzzhenyu-spec/edge-llm-knowledge-map.git
# 双击 index.html 即可；或起任意静态服务器：
python -m http.server 8080
```

## 新增一个知识点（要求与步骤）

所有内容都在 `js/kmap_data.js` 的 `nodes` 数组里。**加一个概念 = 复制下面的模板、逐字段填写、保存刷新。** 页面会自动完成：卡片进入对应分支、首末连线重算、序号徽章、搜索与筛选收录、统计数字更新——无需写任何布局代码。

### 模板（可直接复制）

```js
{
  id: "spec-decode",              // ① 唯一短 id
  domain: "runtime",              // ② 所属领域 id（须已在 domains 登记）
  title: "投机解码",               // ③ 中文短名
  en: "Speculative Decoding",     // ④ 英文/术语名
  level: "进阶",                   // ⑤ 难度，只有两档："入门" | "进阶"
  path: 9,                        // ⑥ 建议阅读顺序（可选）
  oneLiner: "小模型先打草稿、大模型只负责验收——生成快了，答案不变味",
  detail: [
    "第一段：先给直觉与类比……",
    "第二段：机制与关键数字……",
    "第三段：对端侧意味着什么……"
  ],
  keys: [
    "加速 2–3 倍常见",
    "草稿模型参数量约为目标模型的 1/10"
  ],
  related: [                      // ⑦ 关联（可选）
    { to: "tps", kind: "rel", note: "直接提升 decode 的 token/s" }
  ],
  refs: [                         // ⑧ 延伸阅读
    { name: "Fast Inference from Transformers（arXiv:2211.17192）", url: "https://arxiv.org/abs/2211.17192" }
  ]
}
```

### 逐字段要求

| 字段 | 必填 | 要求 |
|------|------|------|
| `id` | ✅ | 全局唯一；小写英文 + 连字符；同时用作深链 `#node/<id>`，起名后不要改 |
| `domain` | ✅ | 必须是 `domains` 里已登记的 id，不存在则概念不渲染 |
| `title` | ✅ | 中文短名，≤ 10 字左右；不用英文缩写作标题（放 `en`） |
| `en` | ✅ | 英文/术语名，全大写或首字母大写均可，展示为卡片与抽屉的副标题 |
| `level` | ✅ | 只允许 `"入门"` 或 `"进阶"` 两档，供筛选 |
| `path` | 可选 | 建议阅读顺序，1 起整数；**全局不重复**；**同分支内连号成块**（如量化分支占 ⑤⑥），避免读者在分支间来回跳；不填 = 不参与顺序 |
| `oneLiner` | ✅ | 一句话白话解释，≤ 40 字；有画面感，不堆术语——它是卡片上唯一的正文 |
| `detail` | ✅ | 2–3 段数组；第一段先给直觉/类比，第二段讲机制与数字，第三段落到"对端侧（手机/本地运行）意味着什么" |
| `keys` | ✅ | 2–4 条，每条一个关键数字或结论；**数字必须带单位**（`14GB`、`10+ token/s`、`约 1/4`、`2–3 倍`） |
| `related` | 可选 | 数组 `{ to, kind, note }`；`to` 必须是已存在的节点 id（不存在会被静默忽略）；`kind`：`"lead"` = 前置（先懂我再看它）/ `"rel"` = 相关互证；**每条边只在一侧登记**（写在任一节点即可），重复登记自动去重 |
| `refs` | ✅ | 1–3 条 `{ name, url }`；`url` 仅接受 http(s)；优先 arXiv abs 页、官方文档、官方博客；发布类事实以官方源为准 |

### 写作规范（六条）

1. **通俗优先**：先直觉与类比，再上术语；术语首次出现给一句白话解释，术语一律用「」引用
2. **数字带单位**：任何关键数字都跟单位，不给裸数字
3. **端侧视角**：每个概念都要回答"这对手机/本地跑大模型意味着什么"
4. **可溯源**：事实性内容能落到 refs 里的原文；不写无法查证的断言
5. **中西文之间留一个空格**（`7B 模型`、`压到 4GB`；渲染层也会自动补齐，但源数据保持工整）
6. **克制**：不写营销词，一段只讲一件事；宁可短而准，不要长而虚

### 提交前自查清单

- [ ] `id` 全局唯一、全小写；`domain` 已在 `domains` 登记
- [ ] `path` 与其他节点不重复，且同分支内连号
- [ ] `oneLiner` ≤ 40 字；`detail` 2–3 段；`keys` 数字都带单位
- [ ] `related.to` 指向的 id 都存在；`refs` 链接可打开
- [ ] 刷新页面：卡片落在正确分支、能被搜索到、序号徽章正确、抽屉内容完整

## 新增公共知识区分享

在 `shares` 数组追加一条（地图下方的链接卡）：

```js
{ name: "Karpathy · 从零手搓 GPT", desc: "两小时逐行写出 nanoGPT", url: "https://…", tag: "视频" }
```

`tag` 建议词表：`视频 / 课程 / 路线图 / 工具 / 报告 / 博客`；`url` 仅接受 http(s)。

## 连线规则（自动生成，无需配置）

- 主干 → 分支节点：每分支 1 条 S 曲线
- 分支 → 概念卡：**每分支只画首、末两条扇形曲线**——加多少张卡，线条数不变
- 跨领域关联（`related`）：默认隐藏，悬停卡片点亮
- 连线坐标运行时按布局计算，节点增删、收起、筛选、换屏都自动重算

## 交互一览

| 操作 | 效果 |
|------|------|
| 点击概念卡 | 右侧抽屉：一句话 → 详解 → 关键数字 → 关联概念（可跳转）→ 延伸阅读 |
| 点击分支节点 | 收起 / 展开该分支（▾ 指示） |
| 悬停卡片 | 点亮它的跨领域关联与邻居卡 |
| 顶栏搜索 | 按标题 / 术语 / 一句话 / 关键数字实时过滤 |
| 难度筛选 | 入门 / 进阶（计数显示在 chip 上） |
| 知识一览 | ①→⑩ 徽章按步弹跳点亮，其余压暗 |
| `#node/<id>` | 深链直开某概念详情，可直接分享链接 |

## 设计说明

- 思维导图的层级（主干→分支→叶子）天然承载从属关系；加概念 = 枝上长叶，加领域 = 多一条枝，任何规模都不乱
- 放弃力导向图谱：节点一多就糊、每次加节点布局漂移，违背"好扩展"的首要目标
- 阅读顺序用"带圈数字常显 + 一览开关"表达，比隐藏的路线图更直白
